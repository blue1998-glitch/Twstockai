使用者原話：「大盤空頭需要很多綜合指標來判斷，因此建議是可以切換日K或還原K模式由人工方式決定分析模式。」

正式方向：提供「原始日 K／還原 K」供使用者手動選擇分析模式。大盤空頭涉及綜合判斷，本階段不以自動市況辨識或回答上一張市場圖為選擇模式的前置條件。這是分析價格基準的選擇，並非只換畫面外觀。使用者沒有在此句指定 B 案例當下選哪一種模式，故本輪不代選。

先前除權息後約2～3月看還原、大盤空頭看原日K的偏好保留為人工判斷背景；不設自動月份倒數、空頭門檻或強制覆寫人工選擇。市場狀態仍可未知，不妨礙使用者明確選原始日K；但這不等於空頭身份或原策略成效已核定。

## 已查的程式事實

- pressure_chart/template.html 與 technical_chart/template.html 已有 id=mode 的「價格基底」選單。
- pressure_chart/viewer.js 的 setupStock 依既存 series 切換；選單以資料 key 指向個別來源，而非僅一組 Raw/Adjusted 布林值。frame.chart_base 指向當前基底，下載含原來源、price_basis、frame 等資料。
- setupStock 的來源選擇順序包括指定 key、preferred_series_by_code、相同 price_mode 及第一組來源。這不等於新人工政策已完整落實；跨個股時預設來源與持續的人工模式意圖需另核，不能先宣稱選擇可保存／所有個股皆可換算。
- 本輪僅閱讀原碼及保存決定，沒有改／執行這些產品程式，也未跑瀏覽器或Android。既有 Adjusted候選或上一輪 B 單次事件研究不自動成為完整還原資料。

## 工程要求（由已確認方向推導，非使用者逐字新增門檻）

1. 主操作清楚顯示「原始日K／還原K」，保留資料來源與方法版本的可查資訊；不存在相應資料時明示缺少項目。不可只改標籤、不可無提示退回另一模式。
2. 人工模式意圖與實際解析到的來源／基底分開保存。外部請求需帶所選模式；引擎不依賴 Streamlit、瀏覽器或介面是否開啟。
3. 同次分析的 K、均線／MACD、壓力支撐與結構參照必須配對同一基底／版本。模式改變時載入相符的已存結果，或建立新的分析版本；不能拿舊 Raw 參照直接放到還原圖、把舊結論只換名。
4. 保存選擇時間、適用個股／截止、模式、實際來源、基底及調整方法版本；舊選擇與結果保留。可恢復既有人工選擇，但資料資格必須重新檢查，且畫面顯示當前模式。不推斷未記錄的歷史人工選擇。
5. 無有效選擇／來源時明確標為尚未就緒，不將大盤分類或預設來源冒充人工選擇。舊凍結結果可照原資格讀取，不因此改歷史資料。成交量沿原口徑另管，不新增量調整。
6. 完整資料驗證仍獨立：人工選還原不會產生缺少的公司行動；選原始也不消除機械除權息落差。B 官方7/1事件已核、完整鏈未核與歷史公開可得限制照舊。
