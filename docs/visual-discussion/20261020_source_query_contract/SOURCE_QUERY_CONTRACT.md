# 單一來源反查契約：擴充既有診斷，不定義自動整體歸屬

狀態：READY_FOR_BOUNDED_ENGINEERING／NOT_IMPLEMENTED。本契約只整理已可精確重現的來源關係，不新增策略核准。前輪使用者確認的不同形態整體概念、局部與整體分判及不提前降低本例舊帶重要性保持。

## 目的與重用

從一個既有轉折ID，查回其原箱、其他尺度同座標來源，以及明示兩來源間的原始有序路徑。這讓整體研究不必先把整個局部箱當成成員。查詢結果不證明同一大帶，也不決定哪些來源更重要。

優先擴充既有graph_diagnostics：其diagnose.py已保存source_turn_sequences、原箱來源、版本及同幾何關係。完整checkout先查是否已有等價反查功能，等價者重用；勿另建第二套轉折／箱／反應事實／圖表。可新增該套件內source_query.py與必要adapter／CLI；不改原diagnose輸出、辨識算法、參數或既有成品。

## 輸入與信任邊界

純函式示意inspect_sources(result, query)：result為一個已保存原graph_core結果，非整個未來資料庫；query只含明示原pivot_ids、path_requests及帶時區的實際selected_at。路徑請求為from_id、to_id，不得隱式猜終點。不得輸入人工月份或價位答案作辨識條件。

先重用原fingerprint／number與驗證程式，驗原schema／result_id、轉折與箱ID引用完整性、原source-prefix/context身分及發生／確認索引時間。每個來源確認不得晚於結果as_of。adapter用原已核來源封包，若輸入的是comparison成品，須驗其完整原artifact/core身分；它內嵌的diagnostics為摘要，不可假裝成完整diagnostic_id驗證成功。不要呼叫diagnose／_pivots／_boxes／MACD重算來做這個反查；也不要因自洽fingerprint就宣稱外部行情或歷史公布時點已核。來源不足或跨基底不一致明確拒絕，不任選同價來源。

純函式無檔案、網路、UI或內建時鐘。CLI／adapter在真正選取時產生selected_at，傳入純函式；同輸入應有相同輸出。資料原可知／原確認、關係不得早於何時可由原確認支持、與後來實際查詢分欄。historical_selection_time=null、historical_signal_eligible=false；不把工具查詢時間回填為當年訊號。

## 精確查詢行為

1. pivot_ids中的每個ID回傳原pivot完整記錄。反向列出所有明確含此ID的原箱及該ID於各source_turn_ids的序位；保留原箱起末、確認、尺度、原來源ID。箱跨到其他月份不裁切、不隱藏，也不自動把整箱列成整體成員。這是原箱source_turn_ids的引用關係，不是人工大帶歸屬。
2. 跨尺度座標對照重用原診斷的來源幾何語義：同segment、種類、發生日、精確數值價位與完整有序source_dates皆相同，列出原ID與各自確認。不同ID始終分開；不得將同價、同日或同確認日的來源任選、合併或獨立計票。只有價格相等而其他欄位不同不回報為完整同來源座標。
3. 每個path_request只接受同scale／segment且順序向前的明示兩來源；按原已確認source_turn_sequences或原pivots的同尺度同段順序取含端點子序列。保留每一中間原轉折、source_dates、確認與原缺證；不能省略末段反彈或用兩點直線替代。跨尺度／段、倒序、未知ID或不在已保存前綴的來源明確拒絕；跨尺度座標對照另列，不自動跳尺度湊路徑。
4. 路徑原確認下限取全部路徑來源確認的最大值；同座標對照取雙方確認的較晚者；原箱引用下限保留箱及來源確認。欄名明示not_before_original_confirmations，並保持歷史公開可得未知。不得只看路徑兩端而忽略中間確認。
5. 額外來源記錄可用ID表去重傳輸，但ID及所有關係不可因同座標刪除。只對顯式pivot_ids做箱反查，路徑可以回傳中間點；不得再遞迴展開全部箱與歷史，避免查一點就無限吸納。
6. 不回傳自動主壓力、結構成員、合併、父子、直接承接、解除、排名或交易行動；相關欄位為null／UNKNOWN，primary_pressure_id=null。原分類及行動資格保持。既有價格重疊或相鄰關係不能經傳遞閉包升格正式大帶。

可採獨立query schema與report_id，但沿用既有精確JSON／fingerprint。輸出包含原result_id、source-prefix/context、原資料資格、完整query及選取時間。輸入深度全等保持；輸出可獨立讀取，無網頁仍可執行。

## 範例與驗收證據（案例只在fixtures，不進生產常數）

- A＝原2023-06-05高39.25的3%ID，應反查B16/B17/B18三個原箱。保留它們六月前的來源及40.25，不把40.25自動納入人工整體；不以月份篩掉A，也不標A為正式大帶代表。
- 原10/24低31.35與11/28高35.50各有3%／6%同座標來源，確認分別不同；原source_dates完整保留。A到11/28原3%高的明示路徑為9筆，末高35.50高於前一高34.15，不能簡化全程下移。A到原6%高不是同尺度路徑，應拒絕該直接請求並分列座標對照。
- 同scale／segment的3%序列全119點，2021-11-29～2026-10-13；9點閱讀路徑前還有33點、後還有77點。用原路徑相鄰自動串接會跨完整歷史，不能用此判整體起訖。這些數字是本fixture，不可當生產迴圈上限或停止條件。
- B77與2022年B6價格重疊但無共享ID／時間交集的反例沿用；不把反查工具改造成合併或傳遞聚類。

必要測試：真實fixture精確ID／原欄位與全中間路徑；多重同價及source_dates差異／不同確認；未知ID、跨尺度跨段、倒序、未確認與混合來源／基底／指紋拒絕；既有前綴在追加或改動未來封包後顯式選同前綴所得查詢不變；純函式確定性及輸入不可變；原core／reaction／MACD／圖表與全部策略參數保存。重用原等價測試；不為湊數寫鏡像測試。每項按實跑記錄，不預填PASS。
