# 獨立資料保存契約 v1.0

固定回傳版本：analysis-store/1.0；本地SQLite檔案格式版本1。數值引擎完全不需匯入資料層，仍能直接接JSON計算；資料層不執行計算、不選擇畫面、不連網。

## 公開入口

| 入口 | 輸入 | 回傳或行為 |
| --- | --- | --- |
| AnalysisStore.create(path) | 新檔案路徑 | 建立本系統資料庫；任何既有路徑均拒絕覆寫 |
| save(request,result,evidence,reason=...) | 已計算的統一工作單與結果、證據JSON、原因 | CREATED或EXISTING、record_id、analysis_id、三份內容指紋 |
| load(record_id) | 精確保存紀錄編號 | 完整工作單、結果、證據、規則參數、首次保存時間與原因 |
| snapshot(record_id,as_of) | 紀錄編號與精確日期 | 該版本當日結構／日均線／對齊快照及涵蓋狀態，不自動改查最近日期 |
| list_records(code=None) | 可選股票代碼 | 保存紀錄清單，以參數化查詢篩選 |
| stats() | 無 | 數量及SQLite實體／外鍵檢查；不代替逐筆JSON內容檢查 |
| recover() | 既有資料庫 | 以可寫方式讓SQLite完成未提交交易復原，再檢查一致性；不建立、不重置、不遷移資料庫 |

使用者不需操作這些程式入口；本版是供後續手機頁面或服務呼叫的本地原型。

## 證據格式

```json
{
  "schema_version": "analysis-evidence/1.0",
  "code": "1101",
  "coverage_status": "UNVERIFIED",
  "records": []
}
```

records可保存已核個案、待查事實、來源資訊與診斷阻擋原因，但不因存入就變成已核實。coverage_status只接受UNVERIFIED或CASH_ONLY_VERIFIED_SAMPLE，不接受全期完成的宣稱。此狀態與工作單本身公司行動涵蓋狀態分別保存，不能互相冒充。

原PDF／HTML來源檔仍隨專案保存；此資料庫保存證據JSON與來源資訊，不宣稱把所有原始來源位元組收進資料庫。

## 四張表的責任

| 資料表 | 保存內容 | 身分與保留規則 |
| --- | --- | --- |
| objects | 工作單、結果、證據、規則的固定JSON | 以種類＋內容指紋去重，保存完整JSON意義，包括null與未核實狀態 |
| analyses | 一次計算版本及其物件關聯 | 沿用引擎analysis_id；相同計算身分若出現不同結果則回報衝突，不覆寫 |
| records | 計算版本與某一證據版本的關聯 | 同計算新增證據可另建紀錄，舊證據與首次時間／原因保留 |
| snapshots | 分析版本×日期的查詢索引 | 保留三個快照ID；完整快照內容保存在不可覆寫的結果JSON |

相同工作單、結果及證據重送回傳EXISTING；不同原因文字不會改寫首次保存原因。來源版本或規則／參數版本改變時，計算身分須不同；舊版本不會變成新版本的內容。單元測試的規則版本分離使用明確空資料標籤測試，未聲稱實作新算法。

JSON接受固定JSON型別、字串鍵與有限數字，拒絕NaN、Infinity及輸入檔重複鍵。數值依來源字串保存，不任意轉為浮點或重新四捨五入。

## 寫入與完整性

save先檢查請求／結果指紋、股票、市場、模式、事件、來源、規則參數、快照對齊及交易資格限制，再將所有物件與索引放在同一筆交易。任何一步失敗都撤回；不回傳半套成功。使用外鍵及禁止UPDATE／DELETE的觸發器，應用介面不提供覆寫／刪除入口。

每次load重新核對保存內容指紋、關聯及快照索引。這是內容一致性檢查，不能認證任意呼叫端提供的官方來源、數字計算或策略品質；直接編輯資料庫檔案的人仍能破壞檔案，不是防竄改安全服務。

程序異常停止後可能留下SQLite復原日誌；工作程序啟動時先呼叫recover再查詢。不要手動刪除復原日誌以消除錯誤。本版已測實際子程序在交易中os._exit，另啟復原程序後舊結果與數量不變；不代表已模擬硬體斷電或磁碟故障。

## 命令入口

以下均在專案根目錄。完整跨程序驗收會使用包內真實結果並可重跑：

```bash
python persistence/run_acceptance.py
python src/store_cli.py stats --db persistence/output/研究資料_v0_9.sqlite3
python src/store_cli.py list --db persistence/output/研究資料_v0_9.sqlite3 --code 8069
python src/store_cli.py recover --db persistence/output/研究資料_v0_9.sqlite3
```

save需--request、--result、--evidence、--reason；load需--record-id；snapshot另需--as-of；--output指定匯出JSON，必須不同於資料庫／輸入檔及其硬連結。回傳碼0成功、2契約或資料庫錯誤、3檔案讀寫錯誤；寫入匯出檔失敗不代表先前已提交的資料庫交易被撤回，可按record_id重新讀取，不應猜測重建資料庫。
