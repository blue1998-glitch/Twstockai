# 單一分析、保存與讀回契約 v1.0

入口：execute_workflow(request,database,create_if_missing=False)。固定請求／回覆版本為analysis-workflow/1.0。這是本地Python呼叫與檔案命令入口，不是HTTP服務或已部署的手機功能。計算仍完全由既有數值引擎執行。

## 三種操作

| operation | 必要資料 | 行為 |
| --- | --- | --- |
| RUN | job、evidence、reason | 驗證→計算→結果核對→資料庫復原／明確建立→保存→讀回；回傳穩定紀錄編號與指定日期快照 |
| READ | record_id | 復原檢查後讀取已保存版本，不呼叫引擎、不改寫分析結果 |
| LOOKUP | 原本完整job、evidence | 依兩份內容的精確指紋查回保存紀錄，不重新計算；不同規則版本若同時匹配，全部列出 |

RUN／READ可選as_of；指定日期不存在即拒絕，不改查最近日期。未指定時選最後一筆保存行情；空資料明示EMPTY_INPUT且snapshot為null。include_bundle預設false，回傳當日快照與必要來源、品質及用途限制；true時另附完整保存工作單／結果／證據，供核對或匯出。

只有RUN可搭配create_if_missing=True；對已存在的檔案仍只復原／讀取，絕不重建或遷移未知格式。錯誤輸入、證據身分不符、無效日期與計算失敗，在初始化資料庫前被阻擋。

## 請求範例

以下省略job與evidence的內容，實際可用範例在workflow/requests：

```json
{
  "schema_version": "analysis-workflow/1.0",
  "operation": "RUN",
  "job": {},
  "evidence": {},
  "reason": "研究樣本分析保存",
  "as_of": "2026-09-30",
  "include_bundle": false
}
```

job沿用stock-analysis/1.0，evidence沿用analysis-evidence/1.0。外層欄位拼錯或include_bundle使用非布林值時拒絕；reason、as_of及匯出選項不改變引擎工作單身分。原始工作單與事件不被修改，不從證據暫存區自動產生核心事件。

LOOKUP只按完整JSON意義精確匹配，包含來源版本與價格模式。回覆FOUND、NOT_FOUND或MULTIPLE_VERSION_MATCHES；後者不自動選最新版本。這是小型研究資料庫的逐紀錄核對，未聲稱達到全市場即時查詢效能。

## 成功回覆

回傳record_id、analysis_id、工作單／結果／證據指紋、價格模式、筆數、規則版本、資料品質、公司行動與證據涵蓋程度、當日結構／日均線／對齊快照與原本用途限制。RUN另有store_status=CREATED或EXISTING，以及commit_status=COMMITTED，表示資料已確認保存或已存在。

COMPLETED僅表示流程完成；computation_status仍明示COMPLETED或EMPTY_INPUT。classification_quality維持NOT_VALIDATED，action_qualification維持NOT_EVALUATED。LOOKUP匹配到版本，不代表來源核實或交易資格通過。

## 失敗與回覆遺失

| commit_status | 含義 | 下一個動作 |
| --- | --- | --- |
| NOT_SAVED | 尚未進入本次保存；READ／LOOKUP本身亦不新增分析紀錄 | 修正請求／檔案問題後再操作 |
| UNKNOWN | 保存呼叫未取得可靠回覆，無法只憑例外判斷有無提交 | 以原job與evidence執行LOOKUP；不要刪除或重建資料庫 |
| COMMITTED | 已確認保存；後續讀回或匯出回覆可能失敗 | 使用回傳record_id執行READ；重跑亦會去重 |

錯誤回覆包含code、path、stage、commit_status及可用的record_id／指紋；不是把所有錯誤都描述為未保存。SAVE階段即使實際已撤回，也保守標UNKNOWN，以查回結果確認；內層資料庫交易保證不留下半套分析紀錄。

## 命令入口與重現

```bash
python workflow/run_acceptance.py
python src/workflow_cli.py --input workflow/requests/8069_ADJUSTED_CANDIDATE.json --db workflow/output/分析流程_v0_10.sqlite3 --create --output workflow/output/單次回覆.json
```

第一行已涵蓋三組完整真實流程、不同程序讀回、精確日期、去重，以及保存後回覆匯出失敗的查回。要從全新資料庫重現，可附加--db workflow/output/另一份流程資料.sqlite3。

CLI使用--input與--db；--create明確允許RUN在缺檔時建立；--output可選。匯出不能覆蓋請求、資料庫、硬連結或-journal／-wal／-shm復原檔。退出碼0成功、2流程／契約／資料庫錯誤、3請求檔或匯出檔問題。匯出失敗後錯誤仍由標準輸出回傳，包含保存狀態。

READ及LOOKUP透過同一workflow_cli讀取對應請求檔，不需要預先製作另一份分析結果JSON。舊analysis_jobs.py與store_cli.py入口維持相容。

## 模組責任與已測範圍

analysis_workflow.py只協調既有引擎與資料層；workflow_cli.py處理檔案與回覆。核心不反向匯入workflow、sqlite3或儲存模組；已在獨立程序禁止這些匯入後，實跑原本引擎成功。

本版不建立網頁、持股／成交帳本、正式訊號、雲端同步或發布服務。分類、交易價值與真實手機驗收仍未完成。詳細實際證據見workflow/output/單一分析保存流程驗收.json與最新完整測試記錄。
