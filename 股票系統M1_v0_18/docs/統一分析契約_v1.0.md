# 統一分析契約 v1.0

本地Python介面run_analysis_job與命令入口src/analysis_jobs.py。不是已部署的HTTP API，也不是手機上傳計算服務。

## 輸入與相容

schema_version為stock-analysis/1.0，其餘必填欄位沿用舊工作單：code、exchange、price_mode、timeframe、source、candles、corporate_actions。只支援TWSE／TPEX日線、明確Raw或純現金除息還原候選，以及既有張數換股數的單位。

舊stock-structure/1.0工作單仍由jobs.py處理，沒有默默切換成較大輸出。新入口轉接舊驗收邊界後，再執行均線核心。兩個核心計算與參數不改動。

## 輸出與對齊

結果版本stock-analysis-result/1.0：

- analysis_id、request_fingerprint及component_versions記錄整次分析的版本。
- shared_input保留共同來源、單位、股票、模式、公司行動覆蓋聲明及共同輸入品質。
- components.structure是舊入口在轉換為舊schema後的完整結果；其中request_fingerprint指向轉換後的舊工作單，新請求指紋在最外層保存。
- components.daily_ma與獨立均線核心輸出相同；原生品質報告不被覆寫，提供日曆的共用對照讀shared_input與對齊紀錄。
- aligned_snapshots連結兩個核心在相同日期、資料內容與已生效事件基準下的快照id。另將當日輸入品質指紋納入聯合快照id；修正過往日曆驗收會形成不同聯合id。

整次analysis_id可隨新增未來資料改變；先前聯合快照id在先前輸入與品質未變動時保持一致。對齊不會把結構、均線或資料品質壓成信心總分，也不產生買賣資格。

COMPLETED代表兩個核心完成運算。EMPTY_INPUT代表沒有可對齊快照，不能誤稱已完成暖機。行動資格一律NOT_EVALUATED。

## 錯誤與檔案

輸入錯誤輸出DATA_ERROR與錯誤位置，命令回傳2；不附半份components。來源、模式、資料／事件指紋、日期或快照數不一致則回報COMPONENT_ALIGNMENT。

檔案先完整寫入同目錄暫存檔並同步，再以替換方式完成；寫入失敗不留下半份新結果。輸入／輸出為同一檔時回傳INPUT_OUTPUT_COLLISION且不覆寫輸入。這類路徑錯誤或輸出失敗回傳3，錯誤寫在標準錯誤輸出。輸出父目錄需存在。

本介面不是來源真實性、完整官方日曆、分類品質、交易績效或歷史可得性的認證。
