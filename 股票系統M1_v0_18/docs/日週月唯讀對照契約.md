# 日／週／月唯讀對照契約 v0.16

## 本次範圍與邊界

這是一個外部唯讀 view model、CLI 與離線頁，不變更 stock-analysis/1.0、analysis-store/1.0、period-analysis-result/1.0、period-file-store/1.0，也不改引擎、門檻或交易資格。對照的是「同一資料輸入與分析錨定是否一致」，不是跨尺度方向判定、可靠度評分或交易結論。

src/cross_view.py、cross_view_export.py、cross_view_cli.py 不 import 任何數值引擎、計算工作流程或資料恢復方法。AnalysisStore 僅用公開 load/list_records，PeriodStore 僅用公開 load/list。讀不動的庫直接失敗，不能修復、重建、選鄰日或改選最新資料。日線三份缺口由獨立 cross_view/prepare_daily.py 明確 RUN 補齊，與唯讀路徑完全分離。

## 明確來源與日期

cross_view/sources.json 為 cross-timeframe-sources/1.0，固定 daily_stores、period_stores、as_of_dates。以別名映射明確庫路徑；CLI 將相對路徑解讀為相對 config 所在目錄，方便整包搬移。as_of_dates 為明確日期清單，不選 max 或最新。跨庫不自動去重或挑版本，版本與保存身分明選。

實際來源包括歷史量能版本並存日線庫、本版獨立補齊日線庫、原週月背景庫。歷史日線六份＋新三份共九份 record；每份取 2026-08-31／2026-09-30 精確快照，共 18 個日線快照。週月 12 份 record，形成 18 種同源輸入對照，所有 12 份週月均有日線對應。before_fill config 刻意只看歷史庫，保留六個週月缺日線的真實案例供缺資料驗證。

## 讀取模型與選取

catalog(config) 回 cross-timeframe-catalog/1.0、exporter_version=cross-view-0.1：

- daily：精確日線快照、原始來源截至日前綴、已生效事件、來源／規則版本／理由／證據涵蓋、原 request/result/evidence 與選取快照指紋。原日線全歷史結果不重複嵌入頁面，完整內容仍在獨立 SQLite。
- period：完整不可變週月保存紀錄、來源別名、身份與快照指紋。
- views：同股票／市場／模式／as_of 的所有組合及各自單邊缺資料視圖，包含對齊檢查、限制及 view_id。單邊視圖不是自動補成完整對照。

select(catalog,selection) 以 cross-timeframe-selection/1.0 固定 code、exchange、price_mode、as_of、daily、period。daily 明指 store＋record_id；period 明指 store＋analysis_id。可以明確傳一邊 null，但不能兩邊都 null。錯誤 ID／日期拒絕，另一個股票或價格模式的明確 ID 會顯示 CONFLICT，不冒充吻合。

結果 cross-timeframe-view/1.0 包含 selection、alignment、原 daily 與 period 資料。view_id 是 alignment manifest 的一致性雜湊；原數值由 snapshot／result／record 指紋追溯，不是來源簽章或防竄改認證。瀏覽器下載與 Python select 輸出完全相同。

## 對齊檢查與限制

必須核對：股票、市場、模式、as_of、選取範圍、producer 支援與版本連結、來源 ID、來源股數單位、日線 structure 的來源與（新版）單位欄位、structure/daily_ma/aligned 的日期、還原錨定、各元件與原來源前綴的資料指紋、各元件與原已生效事件的指紋、資料筆數、最後真實價格日、公司行動涵蓋與選取快照內容指紋。

daily-sma-0.1 的快照沒有獨立 adjustment_anchor 欄位，其已讀取的核心契約規定全條曲線使用該快照 as_of 作錨定；對照層以這項明確版本契約檢查，不偽造欄位。日線 expected_dates 與週月 coverage bounds 語意不同，分別保留，不要求不相同格式的日曆指紋相同，也不以對齊提升日曆認證。

支援日線 structure-0.2-research／0.3-research、daily-sma-0.1、analysis-job-0.1，以及原週月保存層支援的 producer 組合。未知版本拒絕或衝突；不猜語意。structure-0.2 無快照單位欄位，依原 request.source.volume_unit，明示歷史限制；原生股數證據誤標問題另有醒目警告，原證據不改寫。

| 狀態 | 意義 | 展示 |
|---|---|---|
| ALIGNED_INPUTS | 所有保存輸入檢查一致 | 分別展示日／週／月與限制，不生成綜合結論 |
| CONFLICT | 至少一項身分／來源／內容不符 | 停止合併圖表，保留檢查與原資料下載 |
| MISSING_DAILY | 明確缺日線／未選日線 | 只展示獨立週月，日線空白，不補算 |
| MISSING_PERIOD | 明確缺週月／未選週月 | 只展示獨立日線，週月空白，不補算 |

分類始終 NOT_VALIDATED、交易資格 NOT_EVALUATED。來源 ID 是來源聲明，雜湊一致不代表市場來源、公告時刻或交易日曆已認證。

## 頁面與圖表

依序選股票／市場、模式、分析日、日線保存版本、週月保存版本，再按「讀取所選對照」。各版本不預設最新。切換清空舊圖表／表格／下載狀態，找不到所選 ID 不代選。資料矛盾時 hidden 由明確 CSS 規則強制隱藏合併圖。

日線均線 5/20/60/130/260、週線 4/13/26/52、月線 3/6/12/24 全用保存陣列。Raw 日 K 使用原 request 的 OHLC；Adjusted 日 K 未保存於日線契約，本頁只畫保存的還原均線，另列原始價來源 K，不在 JavaScript 推算還原 OHLC。週月 K 使用原核心已保存的聚合 OHLC。紅漲綠跌按 close/open 畫圖；千分位逗號僅在畫圖座標解析時去除，保存字串與下載不改。

週月 elapsed／candidate 切換使用各自保存的值與空值原因。K 棒仍包含已保存的當期資料，明示期間是否走完；已走完口徑只限制 MA，不能冒充日曆認證。不同 as_of 不混在同一價軸。過大數值若無法轉成畫圖座標，保留精確表格，不推算替代值。

轉折發生、首次觀察、確認時間與原狀態分開顯示；區域邊界、接觸、失效、pending 和當日事件均取原快照。沒有在頁面重新辨識轉折、整理或買賣資格。

## 匯出、錯誤與驗收

CLI 支援整份 catalog JSON、指定 selection JSON、HTML；沒有 RUN。輸出先防碰撞：config／selection／模板、SQLite 與 journal/wal/shm、週月庫內檔、symlink／hardlink 別名不可覆蓋。原子寫出失敗保留舊成品。唯讀庫因 hot journal 被擋住時不能自行 recover；只能由獨立有寫入權的既有工作流程恢復，再重新讀驗。

頁面只用 textContent，嵌入 JSON 逸出 HTML/script 邊界，CSP connect-src none，無外部資產、瀏覽器儲存或網路請求。沒有公開部署、付費來源或新服務。

Node 執行真正 inline JS 與實際資料，但 DOM/canvas 是替身。tests/test_cross_view_browser.cjs 已實際嘗試啟動 Playwright；環境缺 Chromium 執行檔，狀態 BLOCKED，不算 PASS。另已準備桌面與手機模擬規格的 18 組切換、下載、錯誤與溢位檢查；物理 Android 仍未測，不能把模擬視為實機。
