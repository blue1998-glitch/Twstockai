# 事件重播比較契約 v1.0

這是純Python、無網頁也可執行的研究檢查入口；不修改既有數值引擎。輸入仍使用stock-analysis/1.0工作單，輸出比較組標示stock-event-replay/1.0。

## 固定入口

`run_event_replay(base_job, reviewed_events)`

- base_job：既有統一分析工作單，包含代碼、市場、日線、來源、成交量單位與資料品質資訊。
- reviewed_events：呼叫端已核對來源的現金事件列。要求code、effective_date、factor、cash_dividend、previous_close、formula與source_sha256；因子須等於28位有效數字HALF_EVEN的(前收−現金)/前收，前收須與本工作單前一筆保存行情相符。
- 不接受空事件組、不同股票、缺少來源指紋、沒有前一筆價格或不同公式。這些檢查只驗證一致性，不能把使用者自填的來源指紋當成官方來源認證。

`make_replay_jobs`建立三份深複製工作單，原輸入不變：

| 工作單名稱 | 價格模式 | 用途 |
| --- | --- | --- |
| RAW_WITHOUT_EVENTS | 原始價格、移除事件 | 刻意移除已知事件的工程對照，不能當正式分析輸入 |
| RAW_WITH_EVENTS | 原始價格、保留已核事件 | 檢查結構邊界重置；日均線仍按原始價格連續計算 |
| ADJUSTED_WITH_EVENTS | 還原候選、保留已核事件 | 檢查各時點只用當時已生效因子，成交量不調整 |

帶事件工作單只標CASH_ONLY_VERIFIED_SAMPLE；沒有事件的對照標UNVERIFIED；均不能代表全期公司行動查齊。

## 固定輸出

- schema_version、request_fingerprint：契約與本次工作單／事件身分。
- jobs：三份工作單；results：三份既有stock-analysis-result/1.0結果。
- report：code、status、checks、boundaries、classification_quality、period_action_coverage、trading_qualification與scope。
- checks每項都有名稱、PASS／FAIL與適用日期／計數。任一項失敗時report.status為FAIL；runner退出碼非0，不把部分檢查通過當完整成功。
- boundaries記錄實際取消候選數、停用區域數、檢查的暖機筆數及原始／還原日均線值。數量來自引擎與比較，不由說明文字產生。

## 來源與轉換邊界

`event_replay/run_comparison.py`是檔案接入層：從包內M0.7原始證據ZIP重查各已知事件的來源雜湊、唯一官方列、純現金條件與現金／前收／參考價欄位，再呼叫獨立重播入口。讀寫檔案不放進分析模組。主流程不連網。

PDF契約公告的`parse_contract_notice`只回傳DERIVATIVE_CONTRACT_ADJUSTMENT_DATE、公文日期及現金事實；stock_ex_trading_date與stock_reference_price維持null。公文日期不是已認證的盤中可觀測時刻。已保存擷取文字與原PDF，離線流程不需要Poppler；重新從PDF產生文字時才需要pdftotext。

目前沒有提供新樣本自動事件升級入口。1101／2884仍沿用v0.7阻擋狀態，不因找到期貨公告、看到月行情X0.00、或完成工程測試而升級。
