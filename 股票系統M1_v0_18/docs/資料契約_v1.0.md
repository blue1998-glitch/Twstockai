# 資料與覆核契約 v1.0

實作版本：structure-0.2-research。這是資料／工程契約，不是新的交易策略。

## 輸入工作單

`data/8069_job.json`、`data/6488_job.json`是完整可執行例子。`src/jobs.py`驗證工作單後才呼叫獨立核心。

必填：schema_version=`stock-structure/1.0`、股票代號、TWSE／TPEX、市場日線、明確價格模式、來源身分、日線、公司行動記錄及其覆蓋狀態。

來源必須包含id、股票代號、交易所及單位。工作單與來源的股票／交易所不同就拒絕。此介面目前只接`SHARES_SCALED_FROM_LOTS`：來源張數換股數，保留來源精度限制；不能把「張」直接冒充「股」。來源欄位是追溯聲明，仍須由上游原始回應核對，不能單憑填入一個id就認證來源。

每筆日線的日期、開高低收是必要欄位。成交量可缺少，但會降低成交量證據可用程度，不用零取代。價格缺失或非法值會阻擋本次計算，不跳過錯誤列後繼續運算。

## 分清楚的資料狀態

| 情況 | 輸出／處理 |
|---|---|
| 缺少必要欄位 | MISSING_FIELD，DATA_ERROR |
| 必要價格為null | MISSING_VALUE，DATA_ERROR |
| 非數字、NaN或Infinity | INVALID_NUMBER／NONFINITE_NUMBER，DATA_ERROR |
| 開高低收不一致 | INCONSISTENT_OHLC，DATA_ERROR |
| 重複／逆序日期 | DUPLICATE_DATE／OUT_OF_ORDER_DATE，DATA_ERROR |
| 沒有任何日線 | EMPTY_INPUT，無快照，不冒充通過暖機 |
| 期間不足以建立波幅基準 | WARMUP，結構未知 |
| 資料足夠但近期波幅為零 | ZERO_VOLATILITY，結構未知 |
| 有合法資料，但當天沒有新增核心事件 | NO_NEW_EVENTS，並非錯誤或「證據不足」的同義詞 |
| 成交量部分／全部缺少 | PARTIAL／UNAVAILABLE，不填零 |
| 未提供交易日曆 | UNVERIFIED，不假裝沒有缺日 |
| 提供的預期日期與實際不同 | DIFFERS_FROM_SUPPLIED_CALENDAR，列出缺少與額外日期 |

日期對照只驗證呼叫方提供的日曆，不認證該日曆來源。本次尚未取得並逐日認證完整官方日曆、臨時休市與個股停牌資料，實際樣本仍標UNVERIFIED。後續不可用單純排除週末的清單冒充官方交易日曆。

## 版本與追溯

- schema_version：資料契約版本。
- rule_version：候選算法實作版本。
- parameters_fingerprint：所有候選參數的穩定指紋。
- data_fingerprint：資料內容指紋。
- events_fingerprint：公司行動資料內容指紋。
- snapshot_id：股票、模式、當日、規則版本、參數及當時前綴資料／已生效事件的指紋。
- event_id：所屬快照id與事件序號，避免不同版本的同日事件混用。

每個快照只用該日以前的價格前綴與已生效事件計算其版本指紋。整份資料的指紋可以隨新資料改變，但未變動的早期快照不應因後一天的價格變動而改變。`source_id`另外保留上游檔案來源關係。

版本指紋用於重現與比較，不是電子簽章，也不證明事件在歷史當天已公告。歷史公告時刻、供應商修訂及完整公司行動仍維持未認證。

## 輸出契約

保留結構狀態、證據狀態、行動資格三組欄位。新增資料品質及事件狀態，不把它們壓成總分。必要欄位、契約版本、日期順序、轉折時間先後、事件id唯一性與未啟用的交易資格會被檢查。

錯誤工作單的命令列介面會寫出DATA_ERROR及錯誤位置，並回傳非成功狀態碼2；不輸出買賣資格。這不代表介面已涵蓋所有可能的資料源或所有JSON Schema驗證條件。

## 人工覆核契約

`output/覆核清單.json`與CSV對每個候選轉折／區域建立獨立覆核目標，綁定原計算版本，初始全為UNREVIEWED。

覆核決定只有ACCEPT、REJECT、UNSURE，必須填理由及覆核者。意義是對候選分類的看法，不是買賣建議或交易價值驗證。修訂必須指向該項目上一筆覆核；原記錄不覆寫。不同版本的結果不能自動沿用舊標記。

紀錄檔使用逐筆追加JSONL，檢查記錄鏈、重複id及損壞資料，寫入時以檔案鎖避免交錯。同一時間的覆核或修訂衝突會拒絕，不靜默覆蓋。

本次沒有新增真實人工覆核。測試只在臨時目錄使用TEST_FIXTURE，沒有把測試意見寫入正式樣本。現有326筆全為尚未覆核，沒有分類準確率；即使以後有接受／拒絕意見，也不能只靠此清單推得漏判率或交易成效。
