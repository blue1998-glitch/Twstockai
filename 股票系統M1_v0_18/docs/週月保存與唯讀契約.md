# 週／月獨立保存與唯讀契約 v0.14

## 範圍

數值由既有 period_jobs 明確 RUN 產生。新資料層匯入完整 request/result；讀取、查詢、匯出與網頁不計算均線，也不 import period_ma、period_jobs、structure、daily_ma 或舊 SQL 資料層。保存邊界只驗證有限 JSON、支援的版本、身分連結、來源前綴／事件／日曆／參數指紋、曲線維度、空值與理由、latest 與曲線對應。雜湊一致不等於來源認證或數學正確性認證；故保留 v0.13 的獨立算術測試，另以不可覆寫衝突檢查保護已存數值。

stock-analysis/1.0、analysis-store/1.0 仍只有 structure 與 daily_ma；沒有 migration，沒有把新欄位加入舊 SQLite。純核心、舊三庫和舊三頁不改。

## 固定版本與內容

- 目錄標頭 STORE.json：period-file-store/1.0，值固定。缺失／不符的既有目錄拒絕開啟，不自動修復或重建。
- 每份正式紀錄 `<analysis_id 去掉 sha256: 前綴>.json`：stored-period-result/1.0，包含 analysis_id、完整 request、完整 result、reason、metadata、record_fingerprint。
- metadata 保存股票、市場、模式、as_of、最後實際價格日、規則／聚合／接入器版本、來源與單位、日曆範圍和認證狀態、參數／request／result／snapshot 指紋。日曆證據的來源檔案指紋仍完整保存在 request.source。
- 現在支援 period-sma-0.1-research／period-bars-0.1／period-job-0.1，並固定該版參數指紋。未知 producer／adapter／schema 或不同參數拒絕；新增支援須有明確讀取器版本與相容測試，不能改字串冒充新版。
- reason 必填、非空、最多 2000 字，亦屬不可變內容。同一分析 ID 更改理由會衝突；若只需再次匯入，用原理由。沒有額外的可改註解或審核帳本。

## 提交、去重與中斷

1. 驗證 bundle，序列化至同目錄 .pending-*；完整寫入並 fsync。
2. os.link 以排他方式建立正式檔名。此處為可見性提交點，不覆寫已存在檔案。其後 fsync 目錄，回報 COMMITTED。
3. 已有同檔名時先完整讀驗；內容完全相同回報 DUPLICATE／COMMITTED，不同回報 PERIOD_STORE_CONFLICT／NOT_SAVED，保留原紀錄。
4. 提交前 I/O 失敗：NOT_SAVED。link 後 fsync 失敗：UNKNOWN 並提供 analysis_id；用 READ/LOOKUP 檢查，不假設未存。
5. 程序被終止時可能留下 .pending-*。讀取不把它當紀錄，diagnostics 列出，絕不自動刪除。link 後即使 pending 硬連結仍在，正式紀錄可直接讀取，不需重算或修復。
6. 本原型使用支援 hard link、檔案／目錄 fsync 的本機檔案系統；不是跨平台、遠端共享磁碟或雲端資料服務。測試涵蓋程序中斷與模擬 I/O 失敗，沒有實際斷電／硬碟故障測試。新目錄初始化先完成，再允許並行匯入；不提供多程序同時建立全新目錄的保證。

目錄的正式檔名就是唯一索引，避免另一份可變索引與內容提交不同步。list 每次完整讀驗全部正式紀錄，壞檔即失敗，不隱藏。此版本只有 12 筆實際保存資料，尚未做全市場、大量快照或多人服務的容量評估。

## 指定讀取，不選最新

Python 公開介面：PeriodStore.create(path)、PeriodStore(path)、save(request,result,reason=...)、load(analysis_id)、list()、lookup(code,exchange,price_mode,as_of, ...)、diagnostics()。開啟與讀取不寫入，初始化／匯入需明確執行。

lookup 必須提供股票、市場、模式、精確 as_of；另可篩選 rule_version、aggregation_version、adapter_version、parameters_fingerprint、source_id。返回全部符合紀錄，可能為空／一筆／多筆；絕不挑最新。load 使用明確完整分析 ID。未保存日不以鄰日代替。多版本在頁面列出明確選項；真實資料目前只有一組 producer 版本，兩版本選單驗證僅用明示合成 UI fixture。

CLI 命令 schema 為 period-store-command/1.0：

| operation | 額外欄位 | 行為 |
|---|---|---|
| IMPORT | request、result、reason | 匯入已算好的完整結果；不計算 |
| READ | analysis_id | 讀取完整保存紀錄 |
| LIST | 無 | 讀取全部 metadata |
| LOOKUP | filters | 精確條件回傳全部符合 metadata |

使用 `python src/period_store_cli.py --store <獨立目錄> --input <命令.json> --output <回覆.json>`。成功 0，資料／契約錯誤 2，部分 I/O／輸出／路徑衝突錯誤 3；以回覆的 code 與 commit_status 判斷，不僅靠退出碼。IMPORT 後若回覆寫失敗，stderr 保留 COMMITTED 與 analysis_id；READ/LOOKUP 可確認保存狀況。若儲存本身 link 後失敗則為 UNKNOWN。輸出不得在庫內、為 symlink，或與輸入／庫檔同路徑或硬連結；輸出採暫存檔 fsync 後 replace，失敗保留舊檔。

## 唯讀頁面

`python src/period_viewer.py --store period_persistence/output/週月結果庫 --output 週月保存結果瀏覽.html`。

匯出器透過公開 read-only 介面完整驗證與嵌入紀錄，不修復。頁面需依序選股票／市場、價格模式、版本、as_of、來源／保存身分。沒有自動最新日；切換清除舊資料，找不到紀錄保持空白。最新值表同時呈現 elapsed 與 candidate，各自保留期間與最後價格日。週／月圖只使用保存的 close 與曲線值；精確表格使用原字串，Number 轉換僅供畫圖座標。

已走完口徑的 MA 排除未走完期間；期間收盤線仍含保存的當期資料，表格明示「尚未走完」。缺值斷線，原因不補 0；成交量完整值與已知部分分開。Raw／Adjusted、來源股數單位、日曆未認證、公司行動涵蓋與完整指紋可見。下載的是完整原保存紀錄。

離線頁以 textContent 放文字、嵌入 JSON 逸出 HTML 邊界，CSP 阻擋網路與外部資產，沒有瀏覽器本機儲存或數值引擎。匯出時的驗證不等於下載後檔案防竄改認證；需比對交付指紋。Node 使用真實 inline JS 與完整真實 bundle，但 DOM/canvas 是替身；真實瀏覽器、Android 開檔／下載、觸控、字體與窄螢幕排版尚未驗收。
