# 股票系統第一階段整合基準規格 v5.4（候選版）

-   文件日期：2026-10-16
-   文件狀態：**整合候選版，尚非正式凍結基準**
-   前版依據：《股票系統基準需求規格 v5.0》（2026-10-05）及後續討論
-   本文件目的：統一核心思想、第一階段範圍、狀態／事件流程、驗收原則與未決事項，避免繼續無限制拆分討論。
-   開發限制：目前仍在規格設計階段；未經使用者明確同意，不開始寫程式、不安裝工具。

## 1. 系統定位與最高原則

本系統不是預測股價的工具，而是以市場狀態辨識、事件偵測、有效 Edge
評估、風險控制與動態資金配置為核心的股票分析與交易決策系統。

核心問題是：在目前可取得的新資訊下，市場與個股處於什麼狀態、發生了什麼變化、哪些機會值得進一步評估，以及資金是否需要重新配置。

### 1.1 不可違反的原則

1.  股票市場是動態平衡系統；新價格可能推翻既有趨勢、支撐壓力或階段判斷。
2.  「未知」「證據不足」「環境未定」「狀態失效」都是合法輸出，不得為了給答案而硬判。
3.  數值引擎是唯一真實來源（Single Source of
    Truth）；所有核心數值與狀態均須可追溯至原始資料及明確規則。
4.  大型語言模型（LLM）只負責語意化、解釋與查詢，不得自行創造核心數值或取代數值引擎。
5.  股票分析引擎必須獨立於操作介面；Streamlit
    只是目前的介面，不得成為核心分析邏輯的依賴。
6.  不把單一技術指標當成未來價格的確定預測；不把支撐壓力視為永久有效的固定價格。
7.  不用無法追溯的綜合分數取代底層狀態、事件、Edge 與風險資料。
8.  風險控制是獨立約束，不能被正向 Edge 抵銷。
9.  規則與歷史驗證必須避免前視偏誤；任何時點的判斷只能使用當時已可取得的資訊。

### 1.2 核心循環

`新資料 → 狀態辨識 → 事件偵測 → 狀態更新／失效檢查 → Edge 重算 → 候選比較 → 風險檢查 → 資金配置評估 → 等待新資訊`

## 2. 市場範圍與資料標準

### 2.1 第一階段市場範圍

-   台灣上市與上櫃普通股。
-   排除 ETF、ETN、權證。
-   興櫃不納入第一階段全市場掃描範圍；如未來需要納入，另行評估資料品質與規則適用性。
-   先以歷史日線完成核心分析及驗證，再擴展盤中更新。

### 2.2 價格與 K 線

系統至少保留兩種價格資料：

-   `Raw`：原始市場價格。
-   `Adjusted`：前復權還原價格，用於處理除權息等公司行動造成的價格斷裂。

介面提供「未還原／還原權值」切換。每次分析、快取、輸出資料與語意說明都必須保留
`price_mode`，不得混用兩種價格而不註明。

K 線顏色全系統一致：紅色代表上漲，綠色代表下跌。

### 2.3 全域時間尺度

-   日線：5、20、60、130、260 日。
-   週線：4、13、26、52 週。
-   月線：3、6、12、24 月。

所有模組共用上述標準。不同時間尺度應獨立判斷與更新，短週期資訊不得直接覆蓋長週期結論。

### 2.4 資料正規化

-   成交量統一以「股」為標準單位，同時保留來源原始單位。
-   成交金額統一為新台幣，同時保留來源原始單位。
-   時間戳可轉換為 UTC，介面以台灣時間顯示。
-   保留來源、取得時間、資料時間、更新時間及品質狀態。
-   未知欄位先保留並標示待確認，不可靜默丟棄。
-   缺漏、重複、異常值及來源差異必須可被辨識與追查。

### 2.5 行情來源原則

-   優先評估免費資料來源。
-   資料來源層與分析引擎分離，方便更換或增加供應商。
-   盤中更新頻率以供應商實際能力及服務限制為準；原先 1--5
    秒是目標方向，不是保證。
-   長期保存所有供應商送達的盤中更新之需求，須在資料量與容量測試後決定保存策略。
-   第一階段先完成歷史日線資料、品質檢查、更新流程及驗收，不讓盤中逐筆保存拖慢核心功能。

## 3. 核心架構與資料流

### 3.1 職責分離

-   **資料層**：取得、標準化、檢查並保存行情。
-   **數值分析引擎**：計算狀態、波段、區域、事件、Edge 與風險。
-   **結果儲存層**：保存原始資料、計算結果、規則版本及歷史判斷。
-   **操作介面**：顯示 K 線、狀態、候選股及證據。
-   **LLM 語意層**：依據已計算結果解釋原因，不另造數值。

### 3.2 儲存與效能方向

既定方向為：

`Parquet（持久化檔案） → DuckDB（分析查詢） → Streamlit Cache（短期快取） → Browser（圖表互動）`

-   Parquet 負責持久化行情與分析資料。
-   DuckDB 負責本機分析查詢與批次結果讀取。
-   Streamlit Cache 只快取適合重用的資料，不取代永久儲存。
-   K 線平移、縮放、十字游標等互動盡可能在瀏覽器端完成。
-   每日收盤後批次計算全市場分析，個股頁主要讀取預計算結果，避免每次切換股票都重算整段歷史。
-   效能目標需以實測驗證；毫秒級讀取是設計方向，不是未經測試的硬性保證。

### 3.3 前端資料契約

核心分析結果以穩定的標準化資料格式（初步以 JSON 為主）輸出，至少包含：

-   股票代號、價格模式、時間尺度。
-   OHLCV 與資料時間。
-   State、Event、Swing、Lifecycle。
-   Edge、Risk 相關結果。
-   證據、確定程度、失效條件。
-   規則版本、資料版本、分析時間。

## 4. 市場狀態 State Dictionary

系統基本單位不是買賣訊號，而是可計算、可驗證、可失效、可重新建立的市場狀態。

初步狀態類別：

1.  價格結構（Price Structure）
2.  波段結構（Swing Structure）
3.  趨勢（Trend）
4.  動能（Momentum）
5.  波動（Volatility）
6.  成交量結構（Volume）
7.  支撐／壓力（Support / Resistance）
8.  相對強弱（Relative Strength）
9.  市場環境（Market Regime）
10. 股票生命週期（Lifecycle Stage）

每一個 State 都必須定義：

1.  定義與用途。
2.  所需原始資料。
3.  計算方式與參數。
4.  成立條件。
5.  失效條件。
6.  狀態轉換條件。
7.  必要、主要與輔助證據。
8.  對 Edge 與風險的影響。
9.  適用時間尺度與價格模式。
10. 歷史驗證方法與適用限制。

在底層 State Dictionary
尚未完成驗證前，不固定最終總分、排名公式或自動交易訊號。

------------------------------------------------------------------------

## 5. 波段轉折與支撐壓力

### 5.1 波段轉折

目的在辨識有分析意義的高低點，而不是把每次微小波動都當成正式轉折。

採混合判斷，至少考慮：

-   相對個股波動程度的價格波幅。
-   持續時間。
-   價格反轉幅度與後續反應。
-   成交量、成交金額及活躍度變化。
-   與既有支撐壓力、整理區及前高前低的結構關係。

不得使用單一固定百分比套用所有股票。不同證據不可簡單等權加總；必要條件不能被輔助證據抵銷。

轉折至少區分： - 潛在轉折。 - 盤中候選。 - 收盤確認。 - 後續修正／失效。

必須分開保存「轉折實際發生時間」與「系統確認時間」。後續修正不可覆寫原先判斷。

### 5.2 支撐壓力區

支撐壓力應以區域表示，不只是一個精確價位。區域形成依據包括：

-   歷史波段高低點。
-   多次價格反應及攻防紀錄。
-   突破、跌破、反彈、受阻與回測情況。
-   成交量、成交金額與交易活躍度集中。
-   與目前整理結構及關鍵前高前低的關係。

每個區域需保存上下界、形成原因、建立時間、測試紀錄、目前狀態與失效條件。區域會隨新資訊更新，不得假設永久有效。

------------------------------------------------------------------------

## 6. 整理結構辨識

整理區不是單純橫盤，而是價格經過一段時間的拉鋸與攻防後，形成可辨識的結構。

評估至少涵蓋：

-   上下邊界與邊界穩定性。
-   持續時間。
-   價格波動範圍及收斂／擴張情況。
-   左側、中段與右側的高低點關係。
-   底部是否穩定。
-   成交量、成交金額與活躍度變化。
-   與關鍵前高及上方壓力的距離。
-   關鍵低點與整體結構是否仍然有效。

### 6.1 三種整理型態

使用者要求三種整理型態都支援。正式命名、互斥／重疊關係及數學定義，必須以既有討論和完整規格為依據，不可只因圖形看起來相似便直接分類。

在正式定義完成前，任何「區間型、收斂／墊高型、底部修復型」等名稱只能當候選描述，不得當成已凍結的正式分類。

### 6.2 整理品質輸出

至少分開呈現：

-   結構品質。
-   右側相較左側的改善或惡化。
-   底部穩定性。
-   突破準備程度。
-   量價證據。
-   主要風險與失效條件。
-   當下證據強度。
-   歷史驗證可靠度與適用限制。

不以單一神秘分數取代上述資訊。

------------------------------------------------------------------------

## 7. 突破、回測與結構失效

突破流程必須區分：

1.  接近關鍵前高。
2.  盤中突破候選。
3.  收盤突破確認。
4.  突破後回測。
5.  動能轉弱但結構尚未破壞。
6.  突破失敗或結構失效。
7.  結構重新建立。

### 7.1 既定交易思想

-   均線不得處於下降趨勢，作為既定候選條件。
-   優先尋找前高之前的整理／沉澱區。
-   偏好右側結構優於左側、中間底部穩定的整理。
-   突破確認以收盤價站上關鍵前高及成交量證據為主。
-   接近收盤的盤中訊號屬次級證據，不可冒充正式收盤確認。
-   觸及前高不等於突破。
-   突破訊號不代表未來必然上漲。
-   必要條件不能被其他正面證據抵銷。

### 7.2 訊號狀態管理

候選狀態包括：

-   觀察中。
-   接近關鍵位置。
-   盤中候選。
-   收盤確認。
-   回測觀察。
-   動能轉弱。
-   結構失效。
-   資料不足／環境未定。

每次狀態變更必須記錄時間、觸發事件、使用規則版本、支持與衝突證據，以及當時可用資料。

------------------------------------------------------------------------

## 8. 證據、確定程度與歷史可靠度

三個概念必須分開管理：

1.  **當下證據強度**：目前價格、成交量、結構與均線證據的完整程度。
2.  **歷史驗證可靠度**：類似條件在已驗證樣本中的結果、樣本數與穩定性。
3.  **適用範圍與限制**：目前股票、時間尺度、市場環境或資料品質是否落在已驗證範圍內。

每條規則保存驗證期間、樣本數、適用市場環境、適用結構、失敗案例與可靠度狀態。

規則適用狀態分為： - 正常。 - 觀察。 - 受限。 - 暫停。

某一市場環境中的退化，不必然導致規則在所有環境全球停用；但資料缺陷、重大規則問題或跨環境失效可以觸發全面暫停。

市場環境分類本身也是待驗證模型。樣本不足時允許輸出「環境未定」。環境轉換需區分觀察、候選轉換與正式轉換；在轉換尚未確認前，不應輸出高確定性正式訊號。硬性風險處理不得因環境未定而延誤。

分類不得無限細分；新分類必須證明能改善決策，並經過足夠樣本與按時間順序的獨立驗證。

------------------------------------------------------------------------

## 9. Event Engine：事件引擎

Event 是新資訊造成的可觀察變化，不是對未來的預測。

初步事件包括： - 突破／跌破。 - 創新高／創新低。 - 趨勢加速／減速。 -
波動擴張／收縮。 - 成交量異常。 - 回撤。 - 結構失效／重新建立。 -
生命週期狀態變化。 - 相對強弱快速變化。

事件觸發後更新相關狀態，並重新計算受影響的 Edge
與風險。事件與狀態變更均須可追溯。

------------------------------------------------------------------------

## 10. Edge、資金配置與風險

### 10.1 Edge 的不同面向

-   **Edge Magnitude**：一次機會可能帶來的有效價格位移／報酬幅度。
-   **Time Edge**：單位時間捕捉有效 Edge 的效率。
-   **Capital Turnover**：資金由一個機會狀態轉移到另一狀態的效率。
-   **Repeatability**：同類機會出現頻率、穩定性與統計證據。
-   **Transition Edge**：新狀態相對目前狀態的增量優勢。
-   **Rotation Edge**：考慮換股成本後，新標的相對舊標的的增量優勢。

上述公式與權重尚未全部定案。Repeatability 不可作為簡單乘數直接淘汰低頻高
Edge 機會；高周轉也不等於高資金效率。

### 10.2 風險控制

風險控制為獨立約束，至少涵蓋：

-   單筆最大損失。
-   最大回撤。
-   結構失效風險。
-   波動風險。
-   流動性、滑價與交易成本。
-   單一標的曝險及整體資金曝險。

既有加碼原則：只有在關鍵位置建立基礎倉位、且動能得到確認後才考慮加碼。加碼後總持倉上限暫按「不超過基礎部位的
2 倍」理解；若後續發現此語意與原始討論不一致，須先釐清再凍結規則。

### 10.3 動態換股

比較目前持股與新候選股時，需同時考慮
Edge、時間效率、風險、結構完整度、Edge
衰減、流動性及換股成本。只有增量優勢足以抵銷成本與不確定性時，才形成換股候選。

## 11. 股票生命週期

理論階段包括醞釀期、初升段、主升段、末升段、出貨期；修正狀態另行判斷。

生命週期不得設計成必然依序前進的固定流程。每個階段都可能失敗、跳過、重新建立或直接轉弱。

每個階段判定至少保存： - `stage`：階段。 -
`confidence`：當下證據強度。 - `evidence`：客觀支持證據。 -
`invalidation`：失效條件。 - 規則版本與分析時間。

------------------------------------------------------------------------

## 12. 第一階段交付範圍

第一階段以盡快建立可驗證的價格結構核心為目標。

### 12.1 必要交付

1.  歷史日線資料匯入、標準化與品質檢查。
2.  Raw／Adjusted 價格模式與資料追溯。
3.  波段轉折辨識。
4.  支撐壓力區形成與攻防紀錄。
5.  整理結構辨識。
6.  關鍵前高、突破、回測與結構失效判定。
7.  當下證據強度、失效條件及判斷歷史。
8.  單一股票歷史重播／驗證流程。
9.  全市場候選股掃描的基本流程。
10. 測試案例、驗收標準與追溯矩陣。

### 12.2 延後項目

-   完整盤中逐筆資料的長期保存與容量最佳化。
-   自動下單。
-   完整券商帳務整合。
-   複雜預測模型及自動調整規則。
-   尚未證明能改善決策的過度精細評分。
-   未經驗證的最終總分、排名權重與自動資金配置公式。

## 13. 歷史驗證與驗收標準

第一階段不能只以「畫面能顯示」作為完成標準。

至少驗證以下情境：

1.  成功突破。
2.  假突破。
3.  長時間整理。
4.  關鍵低點失守與結構破壞。
5.  證據不足、資料異常或市場環境未定。
6.  盤中候選與收盤確認不同。
7.  新資料到來後原判斷修正。
8.  Raw 與 Adjusted 模式可能產生不同結構解讀的情況。

驗收項目：

-   資料正確、缺漏可追溯。
-   波段轉折可追溯，並區分發生時間與確認時間。
-   支撐壓力區有上下界、形成依據與失效條件。
-   整理型態依正式定義辨識。
-   突破各狀態分離且轉換可追溯。
-   當下證據強度與歷史可靠度分開。
-   歷史重播不使用未來資料。
-   全市場掃描使用一致規則。
-   所有結果能回查資料、規則版本、證據與後續結果。

不得預先承諾勝率或報酬。統計結果必須由實際歷史測試得出，並保留未參與規則調整的驗證資料。

## 16. P0-17 多時間尺度均線限制與交易路徑規則 v0.1

### 16.1 決策結果

使用者已確認均線限制採「依交易路徑區分」：

- **轉折型交易**：中長期均線仍下降時，價格結構改善的股票仍可保留為候選；但必須要求更強的結構證據與更嚴格的風險限制。列為候選不代表取得正式買進資格。
- **趨勢延續型交易**：採較嚴格的均線與趨勢條件。若均線與波段結構尚不支持趨勢延續，不得只因短期上漲就通過進場資格。

本決策不代表已指定哪些均線為絕對必要條件；各均線的精確門檻仍須透過歷史案例與驗證確定，不得自行補成固定百分比或固定斜率。

### 16.2 多時間尺度的職責

- **日線**：進場時機、近期波段、整理邊界、突破與回測。
- **週線**：中期趨勢、波段結構及中期壓力背景。
- **月線**：長期趨勢背景與較大尺度的結構風險。

既有均線時間尺度保持不變：日線 5／20／60／130／260；週線 4／13／26／52；月線 3／6／12／24。均線是證據之一，不得取代價格結構。

### 16.3 路徑 A：轉折型交易

必要檢查包括：

1. 整理區或轉折結構可以辨識，且主要關鍵低點及失效條件明確。
2. 檢查左、中、右側結構、支撐防守、上方壓力與波段改善證據。
3. 若中長期均線仍下降，必須明確標示此衝突，不可把均線風險隱藏在總分中。
4. 突破候選、盤中觀察、收盤確認、回測及結構失效必須分開表示。
5. 即使結構改善，仍須檢查剩餘上漲空間、參考下跌空間、進場是否過度延伸、流動性與整體資金風險。

在均線限制的精確門檻尚未完成歷史驗證前，系統可以列入轉折觀察，但不得自動標示為已通過正式進場資格。

### 16.4 路徑 B：趨勢延續型交易

1. 波段高低點與結構狀態必須支持趨勢延續。
2. 均線方向、斜率、排列及股價相對位置需提供相容證據。
3. 若價格結構轉弱或關鍵低點失守，不能因均線仍向上而維持合格狀態。
4. 若均線與波段結構矛盾，標記為等待、限制或未知，依矛盾程度與規則定義處理，不可直接通過。
5. 即使趨勢成立，若股價已過度偏離合理進場區，仍可判定「結構合格但目前不宜追價」。

### 16.5 衝突處理原則

- 價格結構優先於均線排列，但這不代表均線風險可以忽略。
- 均線多頭排列不能抵銷關鍵結構失效。
- 均線下降不會自動否定所有轉折候選，但會提高轉折路徑的證據與風險要求。
- 日、週、月線互相矛盾時，必須呈現矛盾及缺少的確認條件，不得以簡單多數決處理。
- 必要條件、支持證據、風險旗標分開保存；風險不能被正向證據抵銷。

### 16.6 系統輸出

每次判斷至少保存：交易路徑、日／週／月均線方向與斜率、股價相對均線位置、均線排列、波段結構、結構與均線衝突、進場資格影響、解除限制所需條件、資料與規則版本、判斷時間及證據來源。

### 16.7 驗證案例

至少測試：

1. 轉折結構改善但週線均線仍下降。
2. 均線多頭排列但關鍵低點失守。
3. 日線轉強、週線盤整、月線偏弱。
4. 日週月線方向一致但股價已過度延伸。
5. 盤中突破但收盤未確認。
6. 不同股票波動程度不同，避免直接使用未經驗證的統一斜率或百分比門檻。

## 17. P0-18 進場、持有、加碼、減碼與退出狀態轉換規則 v0.1

### 17.1 目的與界線

本節把結構、事件、Edge、Risk、交易路徑及資金容量整合成可重播、可測試的交易狀態流程。系統只提供分析與資格判斷，使用者保有最後決策權；本節不授權自動下單，也不假設每個狀態都必須立即交易。

「股票結構狀態」「交易資格狀態」「實際持倉狀態」必須分開保存。某檔股票可以結構良好但尚未具備進場資格；也可以已持有但結構正在轉弱，需要重新評估風險。

### 17.2 三組狀態

**A. 交易資格狀態**

- `TRADE_WATCH`：一般觀察。
- `TRADE_CANDIDATE`：符合初步結構候選條件。
- `TRADE_WAIT_CONFIRMATION`：仍缺少必要確認。
- `TRADE_QUALIFIED`：通過目前路徑所定義的進場必要條件，僅代表可供使用者評估。
- `TRADE_NOT_SUITABLE_NOW`：結構或進場位置不適合當下交易。
- `TRADE_BLOCKED`：觸發明確必要條件限制或硬性風險限制。
- `TRADE_UNKNOWN`：資料不足、證據矛盾或適用環境未明。
- `TRADE_INVALIDATED`：原候選結構已失效。

**B. 持倉狀態**

- `POSITION_NONE`：目前沒有持倉。
- `POSITION_OPENING_REVIEW`：已取得進場評估資格，尚未確認使用者是否實際買進。
- `POSITION_ACTIVE`：已有持倉，原結構仍有效。
- `POSITION_AT_RISK`：出現結構威脅、波動衝擊或其他風險事件。
- `POSITION_REDUCE_REVIEW`：需評估減碼，但不代表已執行。
- `POSITION_EXIT_REVIEW`：需評估退出。
- `POSITION_CLOSED`：依使用者輸入或已確認交易紀錄，持倉已結束。
- `POSITION_UNKNOWN`：持倉資料不足或無法確認。

**C. 動作評估結果**

- `ACTION_WAIT`：等待新證據或更好的價格位置。
- `ACTION_ENTER_REVIEW`：可評估建立部位。
- `ACTION_HOLD_REVIEW`：結構仍有效，評估續抱。
- `ACTION_ADD_REVIEW`：評估加碼。
- `ACTION_REDUCE_REVIEW`：評估減碼或部分獲利了結。
- `ACTION_EXIT_REVIEW`：評估退出或執行風險處置。
- `ACTION_ROTATE_REVIEW`：與其他候選或既有持倉比較資金轉換價值。
- `ACTION_NO_TRADE`：目前不交易。

上述狀態名稱為初版規格，正式實作前須建立狀態轉換表與測試，不得將評估狀態誤當成已下單或已成交。

### 17.3 進場流程

1. **資料檢查**：資料品質不足時，不能給出正式合格結論。
2. **選擇交易路徑**：判斷為轉折型或趨勢延續型；無法區分時保留未知或觀察狀態。
3. **結構檢查**：確認整理、波段、支撐壓力、關鍵低點及失效條件。
4. **觸發事件檢查**：區分接近關鍵價位、盤中候選、收盤確認、回測及失敗突破。
5. **均線與趨勢限制**：依 P0-17 的路徑規則處理，不可跨路徑套用同一門檻。
6. **Edge 與風險檢查**：評估剩餘上漲空間、參考下跌空間、進場延伸程度、成本、流動性與證據可靠度。
7. **資金與持倉容量檢查**：檢查可用資金、風險額度、集中度及管理容量；若不適合，可保留候選或等待，不必勉強買進。
8. **輸出結論**：合格、等待確認、不適合當下、受限制或未知，並列出依據及缺少條件。

通過進場資格不等於預測將上漲，也不代表必須買進。

### 17.4 持有與續抱流程

持倉後每次更新資料，都重新評估原始進場結構、關鍵防守區、波段高低點、動能、波動、成交活動及剩餘機會。

- 結構仍有效、一般回檔未破壞關鍵防守，且風險沒有觸發硬性限制：可輸出續抱評估。
- 動能減弱但結構尚未失效：標記轉弱與觀察條件，不得自動等同賣出。
- 關鍵低點被跌破或結構破壞：立即觸發風險重評估；不必等待反向趨勢完全確認才處理風險。
- 原進場理由已不成立：保留原始理由與失效事件，重新判斷持有價值，不得以事後理由覆蓋原判斷。

### 17.5 加碼流程

加碼必須重新通過獨立檢查，不得因既有部位獲利就自動加碼。

必要檢查：

1. 已有基礎部位，且原結構仍有效。
2. 出現符合規則的強勢確認或新的有效事件。
3. 加碼後總部位仍符合單檔風險、整體風險、集中度與資金容量限制。
4. 重新計算加碼後平均成本、參考下跌空間及整體損失暴露。
5. 既有「加碼總量不超過基礎部位 2 倍」暫列候選限制，仍待歷史驗證；不得把它視為已證實最優比例。

若結構已轉弱、進場位置過度延伸或加碼會突破風險容量，應拒絕加碼或維持觀察。

### 17.6 減碼與部分獲利了結流程

減碼不能只依固定漲幅或單一指標決定。需同時檢查：

- 股價相對結構參考區是否過度延伸。
- 動能是否減弱、波動是否異常擴大。
- 上方結構空間與剩餘 Edge 是否縮小。
- 原持倉的結構風險是否上升。
- 減碼後資金是否有更具優勢的用途，以及轉換成本是否合理。

「價格偏離過大」可觸發減碼評估，但在未完成歷史驗證前，不可設定成普遍適用的固定賣出百分比。減碼後仍需重新計算剩餘持倉風險與資金配置。

### 17.7 退出流程

退出評估至少區分三種原因：

1. **結構失效退出**：原關鍵低點、支撐防守或交易結構已失效。
2. **機會價值退出／輪動**：其他候選的增量 Edge 足以補償轉換成本、稅費、滑價、判斷不確定性及放棄原持倉機會的代價。
3. **風險或資金限制退出**：整體曝險、單檔風險、流動性或其他硬性限制要求降低風險。

三者原因必須分開記錄。新候選較強不等於必須賣出原持倉；若增量優勢不足，可以保留原持倉或保留現金。結構失效的風險處置不應因等待另一檔股票的趨勢確認而延誤。

### 17.8 狀態轉換基本規則

- `TRADE_WATCH` → `TRADE_CANDIDATE`：初步結構條件成立。
- `TRADE_CANDIDATE` → `TRADE_WAIT_CONFIRMATION`：結構可辨識但必要觸發事件尚未確認。
- `TRADE_WAIT_CONFIRMATION` → `TRADE_QUALIFIED`：必要條件與風險、資金檢查均通過。
- 任一候選狀態 → `TRADE_BLOCKED`：明確硬性限制被觸發。
- 任一候選狀態 → `TRADE_INVALIDATED`：原候選結構失效。
- `POSITION_ACTIVE` → `POSITION_AT_RISK`：出現足以威脅原結構或風險限額的事件。
- `POSITION_AT_RISK` → `POSITION_ACTIVE`：防守與結構重新獲得支持，且原風險事件已依規則解除；不得只憑單日反彈解除。
- `POSITION_ACTIVE` → 減碼／退出評估狀態：依結構、風險、剩餘 Edge 或資金輪動原因觸發。
- 只有使用者輸入或可追溯的成交紀錄才能把評估狀態更新成實際持倉變化。

所有轉換均須保存事件發生時間、確認時間、觸發依據、缺少條件、價格模式、規則版本及判斷時間。歷史重播只能使用當時已知資料。

### 17.9 驗收案例

至少包含：

1. 結構候選形成但未突破，系統持續等待而非提前標示合格。
2. 盤中突破但收盤失敗，狀態可回退且保留歷史紀錄。
3. 收盤確認突破但股價已過度延伸，判定結構確認但不宜追價。
4. 持倉回檔但關鍵低點未破，不能只因短期動能下降自動退出。
5. 關鍵低點失守，風險評估立即觸發，不等待反向趨勢完全確認。
6. 基礎部位獲利但加碼後總風險超限，拒絕加碼。
7. 股價過度延伸但結構未破，輸出減碼評估而不是無條件賣出。
8. 新候選較強但增量優勢不足以補償轉換成本，不強制輪動。
9. 原持倉結構失效但尚無替代候選，仍依風險規則處理，不為了保持滿倉而延遲。
10. 缺漏資料、價格模式不一致或持倉紀錄不明時，輸出未知／限制，不虛構交易狀態。

### 17.10 尚待驗證事項

- 各交易路徑的均線必要條件與具體門檻。
- 整理成熟度、突破確認、回測成立與過度延伸的量化界線。
- 減碼評估的歷史適用性與不同市場環境的差異。
- 加碼比例與總風險限制的合理範圍。
- 狀態轉換在不同股票、波動環境及市場階段下的穩定性。

上述事項以可設定、可追溯、可歷史重播為原則，不在缺乏驗證時硬填固定數值。

## 19. P0-19 進場與持倉決策追溯矩陣 v0.1

### 19.1 目的

本矩陣把交易原則連到具體的來源狀態、事件、資格結果與驗收案例，避免規則只存在於文字敘述中，卻沒有可實作、可測試的對應關係。矩陣是需求追溯起始版，細節仍需隨 State Dictionary 與歷史驗證更新。

| 規則／需求 | 來源狀態或資料 | 觸發事件／必要檢查 | 預期輸出 | 最低測試要求 |
|---|---|---|---|---|
| 資料品質限制 | 資料品質、缺漏、異常、價格模式 | 核心欄位缺漏、時間戳錯誤、Raw／Adjusted 混用或資料來源衝突 | `TRADE_UNKNOWN`、受限或暫停正式資格判定 | 異常資料不能產生正式合格結論；原因可追溯 |

### 19.2 跨規則衝突處理

當多項規則同時觸發時，採以下順序處理：

1. **資料完整性與可用性**：資料不可信時，停止正式資格判定。
2. **硬性風險限制與結構失效**：不得被正向 Edge、均線排列或其他支持證據抵銷。
3. **交易路徑的必要條件**：轉折型與趨勢延續型依各自規則判斷。
4. **進場觸發與價格位置**：確認事件成立仍需檢查是否過度延伸。
5. **Edge 與資金配置**：只有通過必要條件及風險限制的機會，才進行資金優先權比較。
6. **歷史可靠度與適用範圍**：證據不足或超出驗證範圍時，降低資格或標記限制，不得假裝具有已驗證的可靠度。

此順序不是分數權重，也不代表前一項可以自動推導後續結論；每個階段仍須保存自己的狀態與依據。

### 19.3 每次判斷的最低追溯欄位

每個交易資格或持倉動作評估至少保存：

- 股票代號、判斷時間、資料時間、價格模式及使用的時間尺度。
- 交易路徑與目前交易資格／持倉狀態。
- 觸發的 State、Event 及相關證據值。
- 必要條件通過／未通過／未知的逐項結果。
- 支持證據、衝突證據、缺少條件及風險旗標。
- Edge、Risk、資金容量與比較對象（若有）。
- 輸出動作評估、原因、狀態轉換前後值。
- 資料版本、規則版本、計算版本及歷史驗證範圍。
- 後續結果與人工覆核記錄；不得用後來結果回寫成當時已知資訊。

### 19.4 驗收標準

P0-19 最低驗收條件：

1. 每一項正式交易資格結論都能追溯到必要條件及來源狀態。
2. 每個必要條件都能對應至少一個正例與一個反例／失敗案例；若無法建立，標記為待定義或待實證。
3. 資料不足、證據矛盾、硬性風險觸發與結構失效都不能被總分抵銷。
4. 交易資格、實際持倉及動作評估三組狀態不混用。
5. 所有狀態變更都有發生時間、確認時間、規則版本與理由。
6. 歷史重播只使用當時已知資料，並能重現當時輸出。
7. 交易規則、資金配置效果及實際成交結果分開評估。
8. 未經歷史驗證的門檻明確標記，不得描述成已證實有效。

## 20. 盤中點線階梯式強勢結構（整合增補 P0-20）

### 20.1 定義與設計原則

盤中強勢價格運動可呈現「急漲形成高點 → 在價格區域內反覆交易形成橫向整理 → 再度向上推進」的階梯樣貌，但階梯不是必然結果，不以圖形外觀直接判斷可交易性。

- **點與線是動態辨識**：初期急漲高點暫標為 `POINT_CANDIDATE`；若後續多次在相關價位區域成交、停留、回測，可能轉為 `RANGE_BOUNDARY` 或 `CONSOLIDATION_ZONE` 的一部分；原始高點事件不刪除。
- **不能使用未來資訊**：每次判斷只用當時已到達的行情；事後的完整走勢不能回填成當時的即時判斷。
- **價量與時間聯合判斷**：觀察推進幅度、推進速度、整理深度與長度、成交活動、回測次數、價格接受程度、假突破及回落速度；門檻為候選，需用歷史樣本驗證。
- **晚盤不是自動加分**：接近收盤可能有更多證據，但不因時間較晚就自動提升確定性；結構確認與當前價格的風險報酬分開評估。
- **不保證一定是階梯**：急漲後也可能直接回落、擴散震盪或趨勢反轉，必須保留反面證據與失效狀態。

### 20.2 最小事件／狀態模型

`RAPID_ADVANCE_CANDIDATE`（快速推進候選）→ `POINT_CANDIDATE`（局部高點候選）→ `RANGE_FORMING`（整理形成中）→ `RANGE_ESTABLISHED`（整理區已成立）→ `NEXT_LEG_CANDIDATE`（再推進候選）→ `NEXT_LEG_CONFIRMED`（再推進確認）。

旁支狀態：`FALSE_BREAKOUT`（假突破）、`STRUCTURE_WEAKENING`（結構轉弱）、`STRUCTURE_INVALIDATED`（結構失效）、`UNKNOWN`（資料不足）。

上述是**事件狀態，不等於買進資格**。正式進場資格仍須通過原有必要條件、價格風險、資金配置與行情資料品質檢查。

### 20.3 動態點線轉換

1. 新高點先產生候選事件，保存觀測時間、價位、當時成交量、依據及規則版本。
2. 隨後觀測是否形成有效價格區域；高點可能被重分類為區間上緣、區間內部節點或失效高點。
3. 不覆蓋舊判斷：新增 `reclassified_at`、`previous_state`、`new_state`、`evidence`、`data_version`。
4. 階梯可以有多段；每段記錄起點、頂點、整理區間、突破／失敗事件，並與上一段的高低點結構比較。
5. 對於量能，必須先標準化成交量與時間區間，避免直接用不同長度的觀測窗口比較原始量。

### 20.4 分析引擎資料契約

最低輸入：股票識別碼、交易日、交易所、行情事件時間、接收時間、價格、成交量或量增量、累積成交量、資料來源、資料品質、價格模式、資料版本。

最低輸出：`structure_id`、`leg_id`、`state`、`state_as_of`、`first_observed_at`、`confirmed_at`、`supporting_evidence`、`opposing_evidence`、`range_low`、`range_high`、`invalidation_level`、`confidence_basis`、`entry_qualification`、`entry_price_risk`、`rule_version`。

資料粒度不足時（只有每日快照，無逐筆或足夠密集的盤中更新）只能輸出 `INTRADAY_NOT_EVALUABLE`，不得憑日 K 線推測盤中階梯。盤中事件必須保留供歷史重播。

### 20.5 與既有系統整合

- 行情層：盤中事件採集與版本化保存；收盤 K 線仍作正式日線確認。
- 結構引擎：與波段高低點、整理、突破、回測、均線趨勢共用狀態／證據架構。
- 交易資格：盤中候選可提前觀察，但不可冒充收盤確認；進場資格與風險報酬分別輸出。
- 資金優先權：比較當前新候選、原持股與現金，不能因階梯形態漂亮就自動加碼或換股。
- 介面：展示階梯分段、區間上下緣、動態重分類時間與當下有效判斷；點選可看證據。
- 歷史重播：每個時點重建當時可見資料與狀態，防止前視偏誤。

### 20.6 驗收案例

1. 09:30 急漲高點是候選點，10:20 多次交易後重分類為整理上緣，回放 09:30 仍應顯示原候選點。
2. 整理後突破但快速跌回區間，轉為假突破而非確認階梯。
3. 14:00 證據比 10:00 充分，但價格已遠離失效點，結構確認可提升、進場資格仍可下降。
4. 缺少盤中資料時，不可產生盤中階梯正式結論。
5. 盤中強勢但收盤未確認，兩種判斷分開保存。

### 20.7 開發優先順序

先完成 M0 歷史日線與證券名冊驗收；盤中資料供應能力單獨驗收後，實作事件記錄、候選高點、區間形成、再推進、失效與回放。門檻在樣本驗證前維持候選，不設定未經驗證的固定百分比。
