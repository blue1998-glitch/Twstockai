# 週／月背景流程契約 v0.15

本版是一次命令完成的獨立背景工作，不需開啟網頁。它不是持續運行的主機、排程、API 網站或盤中資料服務。純數值引擎與現有保存層不改，外部接入只串接公開介面。

## 輸入與輸出

入口為 src/period_workflow.py 的 execute_period_workflow(request, store_path, create_if_missing=False)，CLI 為 src/period_workflow_cli.py。schema_version=period-workflow/1.0、workflow_version=period-workflow-0.1。操作固定欄位，未知欄位拒絕；資料須為有限 JSON，重複 JSON key 拒絕。新流程不更改原 stock-period-analysis/1.0、period-analysis-result/1.0、period-file-store/1.0 或 stored-period-result/1.0。

| operation | 必要額外欄位 | 可選欄位 | 行為 |
|---|---|---|---|
| RUN | job、reason | include_bundle（布林） | 核心計算一次、驗證、保存、再完整讀回 |
| READ | analysis_id | include_bundle（布林） | 讀指定完整分析 ID，不計算 |
| LOOKUP | filters | 無 | 返回所有精確匹配，不挑選其中一份 |

每個命令還須有 schema_version、operation。RUN 的 job 就是既有完整獨立週月工作單，不接受另一份輸出來冒充新計算；reason 是既有不可變保存理由，1–2000 字。include_bundle 預設 false；false 仍回傳從保存檔讀得的完整 snapshot、metadata 和指紋，true 再附完整 saved_bundle（request/result/理由等）。

READ 的 analysis_id 須為完整 sha256: 加 64 位十六進位身分，身分已固定 as_of，不另選鄰日。LOOKUP 的 filters 必有 code、exchange、price_mode、as_of，可再指定 rule_version、aggregation_version、adapter_version、parameters_fingerprint、source_id、request_fingerprint。所有值須非空字串，日期為有效 ISO 日期。request_fingerprint 用來縮小到原始完整工作單，不需匯入引擎。未知 producer 版本不能被匯入，但指定不存在版本的查詢可回 NOT_FOUND；不因此計算新版。

RUN 成功 status=COMPLETED，附 computation_status（COMPLETED 或 EMPTY_INPUT）、store_status（SAVED 或 DUPLICATE）、commit_status=COMMITTED、analysis_id、request/result/record 指紋、metadata、snapshot、限制與研究資格。READ 的 commit_status=NOT_APPLICABLE，因為沒有寫入。LOOKUP 回 FOUND／NOT_FOUND／MULTIPLE_MATCHES、全部 matches、原 filters、NOT_APPLICABLE；不回單一挑選後的 snapshot。

COMPLETED 僅表示工作流程完成，EMPTY_INPUT 可同時存在，不能拿流程完成當行情或分類合格。缺值保留，分類 NOT_VALIDATED、交易資格 NOT_EVALUATED。

## RUN 的時序與保存語意

1. VALIDATE：先驗 workflow 欄位／reason／JSON，再複製輸入以隔離外部修改。
2. CALCULATE：僅此分支以 lazy import 呼叫既有 run_period_job 一次；數值仍由原核心決定。週月 as_of 是日終，不改成盤中語意。
3. VALIDATE_RESULT：沿用既有保存契約驗結果連結與版本，不重算；不合格不建立庫。
4. PREPARE_STORE：只在明確 create_if_missing=True 或 CLI --create 且操作為 RUN 時，允許建立新庫；其他情況只能開既有庫。READ/LOOKUP 絕不初始化、清 pending 或修復。
5. SAVE：沿用 PeriodStore.save，不覆寫。同身分、完整內容及理由相同，回 DUPLICATE；理由或結果不同就衝突。
6. READ_BACK：收到支援的 COMMITTED 保存回覆後，以明確 analysis_id 完整讀回，核對 request/result 指紋與理由。展示資料來自讀回，讀失敗不使用記憶體結果假裝完成。

本版沒有自動重試。每次明確 RUN（包括手動重試）仍計算一次，保存層去重。回覆不確定時優先 READ／LOOKUP，避免為了確認是否保存而重新計算。沒有跳過核心、選最新或使用網頁快取的捷徑。

## 錯誤狀態與處理

WORKFLOW_ERROR 會保留 operation、stage、code、path、detail、commit_status、已知 analysis_id／request_fingerprint／result_fingerprint 和 recovery_operation。錯誤不改寫原紀錄。

| 位置／情形 | commit_status | 下一動作 |
|---|---|---|
| 驗證、計算、建立庫前失敗 | NOT_SAVED | 修正明確錯誤再 RUN |
| SAVE 已知提交前 I/O 或衝突 | NOT_SAVED | 保留舊檔；有 ID 可 READ 比對 |
| SAVE link 後 fsync 失敗，或保存回覆遭非預期中斷 | UNKNOWN | 用已知 ID READ，或精確 LOOKUP，勿假設沒存 |
| 保存已確認，READ_BACK 失敗／內容不符 | COMMITTED | 保留檔案，再 READ；不回傳記憶體替代品 |
| 保存完成但輸出檔或標準回覆失敗 | COMMITTED | 以錯誤內 ID 由另一個工作讀回 |
| READ／LOOKUP 執行失敗 | NOT_APPLICABLE | 診斷讀取問題，不能補算或重建 |

建立新目錄時的標頭不確定不等同分析結果已存；PREPARE_STORE 尚未開始保存結果，結果仍 NOT_SAVED。SAVE 遇到未分類的例外採 UNKNOWN，避免誤報。程序被直接終止可能沒有錯誤回覆，呼叫端須用精確股票／市場／模式／as_of／request 指紋 LOOKUP；不依有無回覆推測提交成功。

既有本機檔案系統限制照舊：先初始化再並行 RUN，不保證多程序同時初始化全新庫；pending 檔只診斷，不自動刪除。沒有實際斷電／硬碟損壞或遠端共享碟測試。

## CLI 與現成命令

`python src/period_workflow_cli.py --store <獨立目錄> --input <命令.json> --output <回覆.json> [--create]`

成功將完整回覆寫入 output，stdout 回傳小型 OUTPUT_WRITTEN 收據（含 workflow_status、commit_status、ID、PID）。錯誤只寫 stderr 的版本化 JSON，不覆寫既有 output。退出碼 0 成功；2 流程／資料／儲存階段錯誤；3 輸入檔檢查或輸出／標準回覆錯誤。UNKNOWN／COMMITTED 必須看回覆欄位，不能只看退出碼。

輸出不可在保存庫內、為 symlink，或與輸入／庫檔同路徑或硬連結。先檢查再計算；實際輸出採既有暫存檔 fsync→replace，失敗保留舊 output。輸出碰撞檢查是本機單一使用者防誤覆蓋，不是對抗同時惡意更換路徑的服務邊界。

period_workflow/commands 已保留 12 組 RUN／READ／LOOKUP。首次建立獨立驗收庫由 run_acceptance.py 第一個明確 RUN 加 --create；後續工作不建立新庫。命令範例：

```bash
python src/period_workflow_cli.py --store period_workflow/output/背景流程結果庫 --input period_workflow/commands/8069_RAW_CANDIDATE_2026-09-30_RUN.json --output period_workflow/output/操作回覆.json
python src/period_workflow_cli.py --store period_workflow/output/背景流程結果庫 --input period_workflow/commands/8069_RAW_CANDIDATE_2026-09-30_READ.json --output period_workflow/output/指定讀回.json
python src/period_workflow_cli.py --store period_workflow/output/背景流程結果庫 --input period_workflow/commands/8069_RAW_CANDIDATE_2026-09-30_LOOKUP.json --output period_workflow/output/保存查詢.json
```

既有 period_store_cli IMPORT/READ/LIST/LOOKUP 完全保留。驗收刻意沿用原保存理由，讓新流程從相同工作單實算生成的完整記錄與 v0.14 位元組相同，並不代表新 producer 或提高證據認證。新工作接入版本留在 workflow 回覆，不污染數值分析身分。

真實資料仍只有四檔／六種股票模式、兩個分析日。新結果可以沿用原 exporter 與檢視頁，沒有本版新 UI。真實瀏覽器／Android 操作仍未驗收，不能以背景流程或 Node 模擬檢查代替。
